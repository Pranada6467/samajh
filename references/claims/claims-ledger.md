# Claims ledger

This ledger gives every regulatory and factual claim behind `DESIGN.md` a status and a source. Research date: 2026-11-10. The edits that follow from it are in `design-corrections.md`.

## How to read this ledger

- **Part 1** answers group D: each statement in `DESIGN.md` section 11 and section 12 is marked supported, needs rewording, or unsupported.
- **Part 2** has one row per claim for groups A to E. A script builds it from the `findings-<group>.md` files, which hold the full quotes and notes.

| Status | Meaning |
|---|---|
| `verified` | The quoted text is saved under `sources/` and the quote appears in the saved file. |
| `secondary-only` | Only a secondary source (news, law-firm note, vendor blog) supports the claim. |
| `wrong` | A source contradicts the claim. The corrected wording is given. |
| `unverifiable` | No source was found, or the primary source could not be retrieved. |

Six conventions apply to the status column:

1. A qualifier in brackets after the status limits it. For example, "verified (absence finding)" means the saved document was searched and holds no rule on the point.
2. A negative web search ("we found no vendor") is never `verified`. It is `unverifiable`, with the search recorded in the findings file.
3. A vendor's own web page is treated as first-hand evidence of what that vendor markets. It is not evidence of a deployment.
4. Some rows rest on a copy that the issuing body does not host, because the official host served a CAPTCHA or an error. Each such row says so in its status. They are: the RBI FREE-AI report (Medianama copy; E4.3), the SPDI Rules 2011 (PRS India copy; E2.9), IRDAI circular 274/11/2020 (TaxGuru copy; C1.6) and the Baramulla order (scan hosted by LiveLaw; B7). Under a strict reading these four are `secondary-only` until checked against the official copy.
5. The teach-back literature rows C3.2, C3.3, C3.6, C3.7 and C3.8 rest on PubMed abstracts, not full papers. Two papers are saved from non-publisher hosts (Tiwari 2008 in C3.9, Chakraborty 2013 in D1.2).
6. A status covers the quoted text. Where a row adds an interpretation, the row says "our reading".

To repeat the checks offline, run these from the repository root:

```
python3 -I references/claims/check_quotes.py     # every quote appears in a saved source
python3 -I references/claims/build_ledger.py     # rebuild Part 2 from the findings files
```
